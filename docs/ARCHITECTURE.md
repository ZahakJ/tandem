# Tandem architecture

Kotlin and Jetpack Compose, one main activity, no DI framework, and no network unless a feature the user turns on
needs it. Paths below are relative to `app/src/main/java/io/github/zahakj/tandem/`.

## Core

- `TandemApplication.kt` sets up the language before anything shows; `Tx.kt`: `Lang` (the app language, Android
  13+'s per-app language or Tandem's own on 11 and 12) and `Tx` (strings and plurals in it, from any thread; a change
  recomposes both screens in place). See [TRANSLATING.md](TRANSLATING.md).
- `Dates.kt`: every date shown, in the calendar chosen in Settings (Gregorian, Hijri, Chinese, or Gregorian with one
  of them), by `DateKind`; `CalendarText.kt` writes the Hijri and Chinese dates. See TRANSLATING.md, "Dates and
  calendars".
- `MainActivity.kt`: hosts the top-screen UI, maps controller buttons (A select, B back; X, Y, Start, Select, L1,
  R1 go to `Buttons.events`), shows the bottom screen and records play time on return.
- `Platforms.kt` + `assets/platforms.json`: systems and their emulators ("players"). The JSON was generated by
  `tools/platforms.py`, but the script is behind it now: Eden Duo and DroidDeck were added to the JSON by hand, so
  add them to the script before running it again. Users can override it with `ROMs/tandem/platforms.json`. A player
  with `extensions` takes only those files (`LaunchSpec.accept`), and `Platform.playerFor` picks among those that do.
  A player with `"own": true` (`LaunchSpec.owns`) is the only one for its files (`Platform.playersFor`): Moonlight
  for `.moonlight`, streamed PC games in the Windows system.
  `Platform.players` lists installed emulators, default first; `allPlayers` lists all.
- `CocoonPlatforms.kt`: reads Cocoon/Daijisho platform files from `ROMs/platforms/*.json` and turns their
  `am start` lines into players.
- `LaunchIntents.kt`: builds a player's intent (templates like `{file.uri}`, `{file.id}`, `{tags.x}`, typed
  extras), `GameFiles` (ids inside .dpt/.pcgame/.steam), `LaunchDisplay`, `LaunchProblem`.
- `Launcher.kt`: `Launcher.launch(ctx, game)` checks the game can start, plays the launch animation
  (`ui/LaunchOverlay.kt`) and starts it off the main thread: resume via Shizuku, document-URI grants, launch
  display, play sessions (`Sessions`).
- `Emulators.kt`: installed apps, kept current by package broadcasts. `AndroidApps.kt`: launchable apps and the
  Android Games system.
- `Library.kt`: scans every game folder tree, one walk per root (subfolders become groups); `ArtIndex` reads
  `<root>/downloaded_media/<system>/<kind>/`, the game's own root first, then the ROMs folder's.
- `GameFinder.kt` (pure, tested): what a root holds, whatever its shape: folders named for systems (`SystemNames`,
  loose matching of ids, folders, aliases, names and nicknames), a root that is one system's folder, and loose files
  whose extension only one system has (`SystemNames.looseExtensions`).
- `LibraryRoots.kt` (pure, tested): the game folder trees beyond `ROMs` (any folder the user picks; stored in
  `SystemPrefs.roots` with the picker's grants in `SystemPrefs.trees`): the folder picker's document ids as paths,
  what may be added, labels, the merge (the ROMs folder wins a key) and the art lookup order. Managed in
  `ui/GameFoldersScreen.kt`, which also holds the feature's settings rows.
- `FolderWatch.kt`: folder watching while the activity is started (`FolderWatchHost` in `Main`): one `FileObserver`
  over every root, system folder and folder holding a game, plus the storage mount broadcasts; events go through
  `RescanCoalescer` (pure, tested: a few seconds of quiet, never during a scan, one rescan per burst) into a light
  `LibraryScan` pass. Off: `Settings.watchFolders`.
- `Library.kt`: scans `ROMs/<folder>` (subfolders become groups); `ArtIndex` reads
  `ROMs/downloaded_media/<system>/<kind>/`.
- `Manuals.kt`: game manuals and guides from `ROMs/manuals/<system>/`, matched by name like art during the scan
  (`Manuals.index`), or chosen per game (`GameMeta.manual`, copied in by `Manuals.adopt`). `ManualDoc` opens one:
  PDFs through `PdfRenderer`, zips and folders of pictures, text; `PagedManual` draws a page at the width asked for
  and keeps a few in an `LruCache`. `ManualPages` (`manual-pages.json`) remembers the page per game.
  `data/ManualFiles.kt` is the pure part (tested): `ManualKind`, `ManualMatch` (name stems, which file wins),
  `PageOrder.natural` (zip entries as people number them) and `ManualText` (the Markdown subset, cut into pages).
  UI: `ui/ManualReader.kt` (`Route.Manual` on Tandem's screen with the controller; `CompanionManualPanel`, a face of
  the companion, by touch).
- `Collections.kt`: favorites, most played, genres, smart folder contents and other lists from metadata, cached per
  library change.
- `Selection.kt`: what is highlighted (drives the bottom screen), button events, shared `Libraries` state.
- `GameDelete.kt`: which files deleting a game removes and the root/symlink safety checks (popup in
  `ui/DeleteGame.kt`).
- `Running.kt`, `RunningTasks.kt`: one cached Shizuku call (`ps` plus `dumpsys activity activities`) says which emulators have a game open; `RunningGames` maps them to games. A leftover process alone never counts as running.
  `CloseCheck.kt` (pure, tested) decides which running emulators a launch would close, and asks only about those
  with a game Tandem started (`worthAsking`); the question is `ui/CloseAsk.kt`.
- `Bindings.kt` (pure, tested): every `Command` Tandem has on a button with its default `Binding` (a button, a chord or a
  hold), the resolver over the stored map (conflicts, refusals, swaps: `Bindings.plan`), `ChordEngine` (presses,
  holds and chords into commands) and `ChordCapture` (listening on the rebind page, `ui/RebindScreen.kt`). The map
  lives in `controllers.json` (`ControllerStore.bindings`, only the differences from the defaults). Screens keep
  checking logical `Button`s: a command arrives as the button it has by default, and `Buttons.has` tells two commands
  sharing one press apart. Hints ask `Prompts.of` for a command's label, which reads the live binding.
- `Chords.kt`: feeds key events to the `ChordEngine` and carries out the commands (panels, private mode, `Buttons`,
  Open and Back back to the activity as A and B), `Idle`, `Screensaver`, `Privacy` (private mode).
- `PrivacyPin.kt`: the private mode PIN (`PinCode` hashing and waits, `PinVault` in the no-backup folder) and
  `PrivateMode` (on, off and reveal behind it); the keypad is `ui/PinPad.kt`. `Offline.kt`: `NetGate` (nothing goes
  online in private mode) and airplane mode while a hidden game plays (`OfflinePlan`, through Shizuku). It fails
  closed: a hidden game whose launch can't confirm the handheld is offline doesn't start (`LaunchProblem.NotOffline`),
  and with Offline for hidden games set to Until it closes the radios stay off while the game's app runs (`hold`, rechecked every
  20 s).
- `Immersion.kt`: immersion mode, Do Not Disturb with Tandem's own policy (alarms and media only, every visual effect
  suppressed) from `Sessions.start` to `Sessions.take`; `ImmersionPlan` (pure, tested) decides what to change and put
  back, and leaves a Do Not Disturb the user set alone. Access comes from the user or from `cmd notification
  allow_dnd` through Shizuku; what was changed sits in the `immersion` preferences so a restart puts it back.
- `Performance.kt`: performance profiles on AYN devices: the performance mode, fan mode and refresh rate a game plays
  with (`HomeSettings.perf` for all games, `GameMeta.perf` for one), written to AYN's system settings
  (`performance_mode`, `fan_mode`, `peak_refresh_rate` / `min_refresh_rate`, with WRITE_SETTINGS) from `Sessions.start`
  to `Sessions.take`. `PerformancePlan` (pure, tested) decides what to write and put back, skips devices without the
  `performance_mode` setting and AYN's custom fan speed, and leaves a mode the user changed mid-game alone; what was
  changed sits in `performance.json` in the no-backup folder so a restart puts it back. Rows in `ui/PerformanceSettings.kt`.
- `HiddenFolders.kt`: hidden ROM folders and systems (paths relative to ROMs) and hidden icon-grid folders. Ask
  `Privacy.isHidden` / `canShow`, never `GameMeta.hidden` directly.
- `DiscordPresence.kt`: the optional Discord status (play session in, Rich Presence out), behind `DiscordSdk`; the
  backend is `src/discord` (Kotlin plus a small JNI bridge to Discord's C++ Social SDK) when the SDK is in
  `third_party/discord`, else the no-op `src/nodiscord`. Settings in `ui/DiscordSettings.kt`. Its picture is the game's
  cover address (`data/Covers.kt`: `GameMeta.coverUrl` from the scrape, else a lazy lookup; `CoverUrl.safe` lets only
  credential-free addresses out), or the Tandem icon.
- `Achievements.kt`: RetroAchievements client and ROM hashing (`RaHash`); network only when signed in, never for
  hidden games.
- `SteamApi.kt` (pure: Steam Web API addresses, parsing of GetPlayerAchievements, GetSchemaForGame and
  GetGlobalAchievementPercentagesForApp, the merge, the new-unlock diff, account and app id reading) and
  `SteamAchievements.kt` (fetching with the user's own key, the per-game cache in `filesDir/steam/<app id>.json`,
  the age limits, and the look after `Sessions.take` that has Pip announce new unlocks). Network only with a key and
  an account, through `Net` (so `NetGate.check()` first), never for hidden games. The account is in
  `data/SteamStore.kt` (`steam.json`, out of Android's backups); screens and Settings rows in `ui/SteamUi.kt`.
- `Notes.kt`: the device's notifications for the side panel (`NoteListener`, a notification listener the user
  allows; in memory only). Not to be confused with the Notes app (`NoteStore.kt`, below).
- `GameShot.kt` (screenshots through Shizuku), `GameClip.kt`, `ClipService.kt`, `ClipAudio.kt` (15-second clips with
  the game's sound and the microphone), `GameScreens.kt` (a Switch game's own second screen through Eden Duo).
- The Deck, a keyboard and trackpad on the bottom screen for PC games and streams (`GameCompanion.DECK`, offered
  where `DeckGames.suits`): `DeckKeys.kt` (key codes, layouts, sticky modifiers; pure, tested), `DeckPointer.kt`
  (trackpad gain and acceleration, scroll notches, tap classes; pure, tested), `DeckWire.kt` (the `input` lines of
  the shell path and the parcel patching that sets an event's display and action button; pure, tested), `Deck.kt`
  (`DeckOutput` with `BinderDeck`, the input manager's binder through `ShizukuBinderWrapper` by reflection, and
  `ShellDeck`, one `sh` through Shizuku fed `input -d 0` lines; `DeckSession` picks the first that works and keeps
  the pointer and modifiers), `ui/DeckPanel.kt` (the panel and its Settings rows).

## Data

- `data/Store.kt`: persistent JSON in `filesDir` (`library.json` per-game `GameMeta`, `settings.json`). Both are
  Compose state; update with `Store.update(key) { it.copy(...) }` / `Store.updateSettings { ... }`.
- `data/Look.kt`: every appearance, layout, prompt, screen and sound setting (`Settings.look`); `null` fields follow
  the theme.
- `data/SystemPrefs.kt` (`systems.json`): per-system switches, default emulator, bottom screen, extra folders,
  single-screen mode, the game folder trees beyond `ROMs` (`roots`) and the folder picker's grants (`trees`).
- `data/ScanCache.kt` (`scan-cache.json`): folder listings, so startup shows the last scan at once and rescans only
  changed folders.
- `data/Importer.kt`: imports `gamelist.xml` (ES-DE, Cocoon backups).
- `data/HomeStore.kt`: `home.json`, `sessions.json` (play history), `achievements.json` (excluded from Android
  backups). `data/ExtrasStore.kt`: `extras.json`, `journal.json`. `data/IconGridStore.kt`: `icon-grid.json`.
  `data/WidgetStore.kt`: `widgets.json`. `data/ControllerStore.kt`: `controllers.json`. Each store has `reload()`.
- `data/GameStatus.kt` (a game's status, and Playing after a ten-minute session), `data/Trophies.kt` (Tandem's
  trophies, worked out from the data each time; first-earned days in `trophies.json` through `ExtrasStore`),
  `data/Treemap.kt` (the by-system mosaic in Stats), `data/SteamArt.kt` (store art for `.steam` shortcuts after a
  scan, never for hidden games or in private mode).
- `data/Backup.kt`: versioned backups in `ROMs/tandem/backup/<yyyy-MM-dd_HH-mm-ss>/` with a `manifest.json`, in four
  categories, restored category by category; automatic ones before big changes (last five kept). UI in
  `ui/BackupScreen.kt`.

## Scraping

`data/Scraper.kt` runs the job (singleton scope, pauses in the background) and the per-game worker, which asks
sources in the user's order, each only for what is still missing. `ScrapeHits.kt` (`RunSources`: lookup and pace
per source), `ScrapeSources.kt` (network, saving media, libretro, ScreenScraper, SteamGridDB, matching, hashing),
`ScrapeApis.kt` (IGDB, HowLongToBeat), `LaunchBox.kt` (pure Kotlin streaming parser and on-device index) and
`LaunchBoxDb.kt` (download, monthly refresh), `DetailsFill.kt`, `ScrapePlatforms.kt`, `SourceTests.kt`,
`ScrapeConfig.kt` (settings and keys, in their own private file). `GameMeta.lockedFields` marks user edits a scrape
keeps. UI: `ui/ScrapeScreen.kt`, `ui/ArtSetup.kt`, `ui/GameEditor.kt`. See [SCRAPING.md](SCRAPING.md) and
[PRIVACY.md](PRIVACY.md).

## The second screen

- `ui/BottomScreen.kt`: the second display as a `Presentation`, showing details for the current `Selection`. With
  the screens swapped it draws the library and `MainActivity` forwards the D-pad and A to it; `ControlsGuard`
  (`ui/ScreenRoles.kt`) swaps back if it cannot take the controls.
- `GameCompanion.kt` + `ui/CompanionScreen.kt`: the bottom screen during play. `CompanionActivity` opens on the
  second display before the game (own task, out of Recents, `FLAG_NOT_FOCUSABLE` so the game keeps the
  controller) and is dismissed once the presentation is back, or closes by itself once its game's task is gone
  (`GameExit.kt`). Modes: `art`, `tandem`, `dark` (Screen off) and `off` (Leave to emulator, the default for
  dual-screen emulators); the game's choice beats its system's, which beats the setting for everyone
  (`HomeSettings.companion`, `CompanionMode.resolve`). `CompanionRestore.kt`
  reopens it if Tandem's process restarts mid-game; one left behind by a restart goes with the next dismissal.
- `ScreenOff.kt`: the bottom screen going dark during play (pure, tested): bright, dimmed or dark from the mode, the
  Off after timer (`HomeSettings.companionOffAfter`) and the last touch; a dark panel is one black, still box with
  nothing composed under it, lit again by a touch (the first touch only wakes), by Home bringing the game back
  (`GameCompanion.wake`) or by coming back on show. Its header explains why it is black pixels and not a window
  brightness of 0 (one brightness override for every display on Android 13) and what `dumpsys display` is asked
  for the log (`logFacts`). Settings rows in `ui/ScreenOffSettings.kt`.
  `GameResume.kt` brings a running game back by its own task (never a new one). A task that is a
  picture-in-picture window (`mode=pinned` in the dump, `RunningTasks.Activity.pinned`) stays small when moved to
  the front, so for those the app's launcher intent is started: Android hands it to the pinned task and opens it up. `HomeBack.kt`: Home with another
  app over a running game brings the game and its companion back first; a second Home goes to Tandem.
- `SecondaryHome.kt` + `ui/SecondaryHomeScreen.kt`: Tandem's secondary-display Home, shown when nothing else is
  on the second display and Tandem is the default Home. It is `singleTop` (Android refuses `singleTask` for a
  secondary home), not focusable and out of Recents. It shows the app in front or Pip over a still wallpaper, and
  dims after a minute. Android's own launcher opens only when the user picks it (`openStockHome`,
  `openStockBottom`).
- `TandemDream.kt`: Tandem as Android's screensaver. On the Thor, controller input goes to the presentation of the
  app behind a dream, so the dream shows its own `Presentation` on the second display (`DreamBottom`) that wakes
  on any input, and every Tandem window checks `Dreaming.onKey` / `onMotion` first. `WakeGate` (`DreamWake.kt`)
  swallows the rest of the waking press.

## Conventions

- **Controller first.** Every screen is fully usable with the D-pad and A/B. Every focusable thing is a
  `FocusCard`; screens pick the target with `rememberFocusTarget`, attach `takesFocus` and keep it in view with
  `KeepInView`. Popups use `OverlayPanel`, which makes them a focus layer.
- **Text.** Everything the user reads comes from `res/values/strings_<area>.xml` through `Tx` (`Tx.kt`, with `Lang`,
  the app language), never written in the code: see [TRANSLATING.md](TRANSLATING.md).
- **Dates.** Every date the user reads goes through `Dates` with a `DateKind`, never a formatter of its own, so the
  Calendar setting reaches it. Saved and exported dates stay ISO.
- **Sizes.** The top screen is about 830×470 dp, the bottom about 470×540 dp (see [UI-RULES.md](UI-RULES.md)). Keep text readable at arm's length.
- **Style.** Pastel `Palette` colours on the night background, rounded 14–26 dp corners, spring animations, Pip for
  empty states and messages. Friendly, plain text.
- **Privacy.** No analytics or telemetry. Network only for features the user turns on. Never send hidden games
  anywhere.
- **New features** go in new files; keep edits to shared files small. A feature's settings are a
  `@Composable fun xxxSettings(): SettingSection` in its own file, added to `settingsCatalog()`.
- **Build** with `./gradlew assembleDebug` (on NixOS, `nix-shell --run './gradlew assembleDebug'`) before
